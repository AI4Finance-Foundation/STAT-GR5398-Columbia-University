Unresolved defects, by priority

1. Labels for decision dates on or after source_event (prep, code bug).

The label only goes NaN when date < source_event <= end. A decision date equal to source_event with a row on that day has entry=True.
If exit_day > date, the interval (date, end] then includes the deferred terminal return. That return was realized on or before the entry close, and the backtest correctly refuses the trade by freezing it.
If exit_day == date, the label is 0.0 under “observed_CRSP_total_return” for a security that is already gone.
Fix: assign NaN with a distinct status whenever date >= source_event.
Query: count panel rows with decision_date >= crsp_return_date for event PERMNOs.

2. tradingstatusflg may still carry ex-post information (prep, data check).

Removing dlydelflg only helps if tradingstatusflg=='A' on a security’s last row is also known ex ante.
I’m not certain of CIZ’s code set, so check whether the terminal row carries ‘D’ or another non-‘A’ code. If it does, the same look-ahead survives, and your no_filter_on_future… receipt is false in substance.
Check: compare the entry flag on each last row against its value one session earlier.

3. Unchanged headline numbers mean the new branch is unexercised or a no-op.

Report max(pending_exit_weight), the row count of held_exit_events.csv, and the number of rebalances where frozen & (w>0).
If all are zero, the sell-side logic has never run on real data. Add a synthetic test that forces a held name through a deferred event (source_event < exit_day) plus a rebalance inside the window, with hand-computed dollars.

4. Sensitivity runs can overwrite headline outputs (backtest).

FINRL_REMOVE_RIGHTS=1 writes to the same OUT directory, which holds nav.csv, comparison.csv and *_selected.csv.
Unless FINRL_RUN_DIR differs, the ledger audit may compare against a mismatched run.
Key the output directory on the sensitivity flag, and write the flag into the outputs.
