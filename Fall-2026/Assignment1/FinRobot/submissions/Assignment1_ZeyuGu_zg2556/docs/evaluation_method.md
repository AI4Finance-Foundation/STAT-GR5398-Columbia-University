# Independent grounding and stability evaluation

These scripts implement evaluation; code and passing unit tests are not experimental results. Genuine outputs exist only after completed real generation/evaluation calls. Evaluation is machine-assisted. No human annotation or validation is claimed.

## Grounding unit and coverage

`scripts/grounding_audit.py` uses its own instruction set and Pydantic schema, separate from the ninth-stage verifier. The auditor receives the actual saved section text and the exact evidence prompt captured for its original generating agent. It is never given verifier classifications. A final/revised report is audited with `--evidence-run` pointing to the baseline generation, so added external evidence cannot retroactively support an original claim. The script checks typed response text against the saved original text and validates source/prompt hashes. All eight sections are mandatory.

Version 2 deterministically partitions every nonblank source line into conservative sentence units before the model call. Decimal points, common abbreviations and initialisms do not split sentences. Every source unit ID must appear once, with all atomic claims or a specific nonfactual explanation. The model does not copy source text or offsets: code reconstructs exact quotes from immutable spans. Omission and duplication fail validation. Larger compound units still require every atomic premise to be extracted. Offsets are zero-based, end-exclusive Unicode character positions in Python's newline-normalized saved text. Original file hashes are checked independently.

This proves textual coverage, not that an LLM has recognized every semantic proposition. Compound sentences still require machine judgment to decompose, and the model could incorrectly call a factual premise nonfactual. `text_coverage.csv` retains every such decision for subsequent review. Do not describe this as exhaustive human validation. The full claim inventory and coverage file, not a few sampled sentences, are the evaluable deliverables.

Supported means entailed or arithmetically derivable from the original prompt. Unsupported means insufficient supplied evidence, regardless of outside truth. Contradicted means the original evidence positively conflicts. Every supported/contradicted record needs valid evidence line ranges. Code fills the exact original quotation from those indices, so generated quotes cannot accidentally omit table rows or change whitespace. Semantic judgment must still establish the relevant company, period, unit, actual/forecast column and comparison scope. Universal qualifiers such as “consistently” require all visible comparable actual observations; a counterexample is a contradiction. A forecast is not evidence of historical performance. Warning labels such as “Unverified” do not turn the underlying unsupported assertion into a supported statement about a draft. Numerical labels are `correct`, `incorrect`, `unverifiable`, or `not_numeric`; numbers must refer to the right entity, period and units. No generic numeric-string match is treated as semantic proof.

CSV results contain run/company/section, source hashes and offsets, atomic claim, classification, numeric status, precise evidence and rationale. Rates are weighted counts: grounding = supported / all claims; contradiction = contradicted / all claims; numeric error = incorrect / all numeric claims. A second numeric error rate divides only by verifiable numerical claims. Unverifiable numeric counts are always printed so apparent accuracy cannot improve merely by excluding them. Empty sections have `N/A`, never 100%.

Interrupted audits can be continued with `--resume` using the identical command/settings. A fingerprint binds source/evidence hashes, model, provider, output schema, instructions and generation parameters. Successful section responses are revalidated and skipped without a new call. Every request is stored under `calls/SECTION/attempt_NNN`; failed attempts remain intact, and `selected_attempt.json` identifies the response used for scoring. `--repair-attempts 2` permits at most two additional schema/coverage calls per section, across resumes. Repairs use the identical source and evidence plus a validation diagnostic; they cannot add external evidence. HTTP/transport failures stop the run. HTTP-200 schema failures may be repaired within the explicit budget, with unresolved billing reservations retained and reported. Cost totals include unsuccessful completed attempts; unresolved billing is listed rather than silently treated as free.

The version 1 trial required the model to reproduce paragraph whitespace and evidence ranges verbatim. Three real tagline attempts failed deterministic validation, and their original calls/errors remain preserved under `audits/grounding/NVDA_before`. No failed attempt contributes scored claims. Version 2 removes the brittle copy task while keeping the original evidence boundaries; all scored before/after audits must use the same v2 instructions and schema. This engineering correction does not prove the model’s semantic labels are correct.

## Before/after and information retention

Audits must use identical baseline evidence hashes, the same independent auditor instruction hash and model. The comparison checks the final run's parent ID and ensures the verifier's saved revised text equals the audited final text. The claim map links verifier original spans to independently extracted baseline claims by overlap; verifier judgments are preserved for traceability but are never reused as audit labels.

The scorecard reports grounding, contradiction and numeric error rates, total and supported claim counts, after/before claim-count ratio, retention of independently normalized supported fact keys, retention of supporting evidence spans and the verifier's own retention count. Fact keys and evidence spans are complementary proxies: paraphrases can receive different keys, and multiple facts can share a table line. Their limitations must accompany the reported results. High grounding paired with lost facts is not sufficient evidence of improvement. `remaining_errors.csv` keeps all independent unsupported/contradicted final claims; `claim_retention_mapping.csv` exposes deletions and corrections. Verifier extra token/cost/runtime totals include unique canonical and archived billed attempts within each final run. `verifier_attempt_costs.csv` lists them; attempts without a structured response are exposed as unresolved billing rather than assigned zero cost. Separately abandoned runs remain part of global experiment costs. Totals are repeated on section rows for context and must be counted once per company, not summed across rows. Verifier-reported visible retention and verified retention are separate: an annotated unsupported proposition can be visibly retained without becoming verified. Cohort rows aggregate counts instead of averaging company percentages.

At least three distinct companies are required by the comparison command; `--allow-partial` is explicitly labeled incomplete and is only for development. Different stages may use the same model family, so a distinct evaluation prompt reduces but does not eliminate correlated errors. A human reviewer would still be necessary to claim human-validated labels.

## Stability

`scripts/stability_audit.py` requires at least three completed baseline runs. It rejects differences in ticker, fixed upstream revision, frozen file hashes, evidence hashes, model, temperature and output budget. For every one of the eight sections it checks identical canonical actual wire requests, distinct provider completion IDs, distinct HTTP request IDs where provided, distinct call IDs, successful HTTP status, reported token usage and positive runtime. The typed output must match the saved wire JSON content. Copied cache responses fail this check. Provider IDs are supporting execution evidence, not signed billing receipts.

An independent extraction call per run lists explicitly stated writer recommendations and target prices, separately from attributed analyst/FMP views. Missing or conflicting recommendations remain `N/A`/conflicting; optimistic language is not converted to a Buy and enterprise value is not converted to a share-price target. Every extracted field retains its exact unique source span. Rating normalization maps explicit terms to strong buy/buy/hold/sell/strong sell; its ordinal encoding is a reporting convention rather than a cardinal financial distance. Target prices retain currencies and stated horizons. Incompatible currencies/horizons and unknown currencies prevent an economically comparable target summary.

Risks use a fixed taxonomy listed in the script. The top three are the first three distinct categories encountered in the actual risk narrative. This is a reproducible first-mention ordering, not a claim that they are the economically most material risks. Full extracted risk quotes remain available. Pairwise Jaccard compares the category sets; Kendall tau compares the order of shared categories and is `N/A` with fewer than two shared categories. A broad taxonomy can overstate agreement and should be read alongside the quotes. Sample numeric variance uses the n-1 denominator. Missing observations remain missing, and three runs provide only weak precision for estimating stability.

FMP rating and target are read separately from each frozen `market_snapshot.json`, including its `_provenance` map. Their zero variance only proves fixed-input reuse; it says nothing about LLM stability. Generation tokens, cost and runtime are separated from the extra extraction calls.

## Commands

Run these from the submission directory after `experiment.py` has produced the named run directories. Paths below define intended artifact destinations; they are not claims that those experiments have already run. Use the dedicated environment's Python executable and a private approved budget/config file. All paid commands use the same serial ledger; never run them concurrently while that ledger is locked.

```powershell
python scripts/grounding_audit.py run --run runs/NVDA_baseline_1 --output audits/grounding/NVDA_before_v2 --config $env:FINROBOT_CONFIG --budget $env:FINROBOT_BUDGET --ledger evidence/costs.jsonl
python scripts/grounding_audit.py run --run runs/NVDA_final --evidence-run runs/NVDA_baseline_1 --output audits/grounding/NVDA_after_v2 --config $env:FINROBOT_CONFIG --budget $env:FINROBOT_BUDGET --ledger evidence/costs.jsonl
python scripts/grounding_audit.py summarize --audits audits/grounding/NVDA_before_v2 audits/grounding/AMD_before_v2 audits/grounding/INTC_before_v2 --output audits/grounding/baseline_summary
python scripts/grounding_audit.py compare --pairs audits/grounding/comparison_pairs.json --output audits/grounding/before_after
python scripts/stability_audit.py --runs runs/NVDA_baseline_1 runs/NVDA_baseline_2 runs/NVDA_baseline_3 --output audits/stability/NVDA --config $env:FINROBOT_CONFIG --budget $env:FINROBOT_BUDGET --ledger evidence/costs.jsonl
```

`comparison_pairs.json` is an array of objects with `before`, `after`, and `final_run` directory paths, one per company. Before/after directories must contain completed independent audit manifests and their claim CSVs; no labels are generated by `compare`.

Grounding `summarize` and `compare` are offline. For stability, replay saved extraction responses and recompute all derived metrics without another model call:

```powershell
python scripts/stability_audit.py --runs runs/NVDA_baseline_1 runs/NVDA_baseline_2 runs/NVDA_baseline_3 --offline-extractions audits/stability/NVDA --output audits/stability/NVDA_replay
python -m unittest discover -s tests -p test_evaluation.py -v
```

Offline replay does not count as a new independent generation. It preserves historical extraction cost and reports zero incremental extraction cost for replay. Unit tests use visibly synthetic fixtures only inside temporary directories; they are not copied to experimental outputs or scored as research results. No provider request is made on module import, unit testing, grounding aggregation or offline stability replay.
