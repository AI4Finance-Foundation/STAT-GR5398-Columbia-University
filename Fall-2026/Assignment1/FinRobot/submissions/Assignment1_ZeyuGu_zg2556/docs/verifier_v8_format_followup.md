# V8.1 development: exact numeric display wrappers

The unchanged-evidence GPT-5.4 pilot with low reasoning effort completed one NVIDIA company-overview section: 4,372 input tokens, 8,497 output tokens (including 1,400 reasoning tokens), $0.138385 and 73.7647 seconds. This was a new draw with different reasoning parameters from the failed high-effort pilot, not a stability replicate or cached success.

Its real response exposed a deterministic transport defect. The model bound literal `2025A` to the identical cited header label; the old numeric tokenizer extracted `2025` and the automatic year repair added a second key, rejecting a valid corrected sentence. Currency-wrapped tokens and sentence-final commas caused similar binding mismatches. All original request/response/error bytes remain unchanged.

V8.1 permits a narrow normalization only for identical actual/forecast year or currency wrappers, present exactly in the revised claim and stated evidence line, with identity conversion. It preserves the original bindings, displayed A/E suffixes, evidence and an explicit alias map. It adds no reference, value, judgment or text. Different periods, A/E labels, currencies, uncited values, duplicates and nonidentity conversions remain rejected. Its numeric tokenizer includes only actual three-digit grouping commas. The initial V8 development source is retained separately; V8.1 corrects terminal-punctuation matching before empirical revalidation.

Clean patches at `evidence/verifier_versions/patches_v8_1` apply to upstream `2717499b8e30f242640af08c4ad9afd1113c2d45`; the clean copy passes 124 offline tests and six subtests. Tests are control fixtures, not financial experiments. Offline revalidation of the real low-effort response reduces deterministic failures from12 to1 and accepted revisions rise from0 to11. This is a transport result, not a semantic accuracy estimate. The remaining rejected news claim uses an Article1 reference without citing its source line; the guard appropriately does not invent that reference.

Its proposed endpoint-value replacement is numerically supported, but the mistaken original classification and lost inequality information remain important failure evidence.
