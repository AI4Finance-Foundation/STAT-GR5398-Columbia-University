## 3. Project Updates and Additional Details in the Medium Report

### 3.1 Baseline Pipeline Fixes and Engineering Enhancements

Before comparing different models, I first improved the baseline FinRobot pipeline. This was necessary because the model comparison would only be meaningful if each model received a similar set of structured inputs and if the report generator could correctly read those inputs.

The main baseline pipeline improvements include:

- Connected additional structured analysis artifacts to the final report-generation step.
- Added and checked support for peer EBITDA comparison.
- Enabled sensitivity analysis and connected `sensitivity_analysis.json` to the report.
- Enabled catalyst analysis generation when news data is available.
- Configured retail sentiment output when the required API key is available.
- Corrected the competitor analysis input so the report uses `competitor_analysis.txt` instead of incorrectly passing a CSV placeholder.
- Added PDF report generation so the final output can be exported as both HTML and PDF.

These changes made the pipeline more complete and helped ensure that every model was evaluated using a more consistent and meaningful report structure.

### 3.2 Track A: Base Model Replacement and Multi-Model Experiments

For Track A, I tested several base models and model configurations.

The main experiment groups include:

```text
baseline_gpt41
exp1_gpt4o
exp2_claude
exp3_gemini
exp4_claude_gpt4o
exp5_claudeplugin
exp6_gpt4o  # GPT-4o setup used to test whether Track B can be turned on/off
```

The required companies covered in the assignment are:

```text
NVDA
AMD
INTC
AAPL
GOOGL
```

For each model configuration, I generated equity research reports for the five required companies and organized the outputs by experiment and ticker.

A key issue I found during the experiment was that the pipeline originally used different models in different stages. The financial analysis stage used the model specified in `config.ini`, but the report regeneration stage could fall back to another model such as GPT-4o-mini. This created a model-consistency problem because a report that appeared to be generated by Claude or Gemini might actually have been partially rewritten by another model.

To solve this, I added optional regeneration-model settings:

```text
openai_regen_api_key
openai_regen_base_url
openai_regen_model
```

This allows the pipeline to support two modes:

1. Use the same model for both financial analysis and report regeneration.
2. Use different models for different roles, such as one model as the main analyst and another model as the report writer or editor.

This made the model comparison more controlled and reproducible.

### 3.3 Model Comparison Summary


| Model / Setup           | Main Strength                                                  | Main Limitation                                                                  |
| ----------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| GPT-4.1                 | Stable and complete baseline reports                           | Sometimes more descriptive than analytical                                       |

| Claude Sonnet 4.6       | Strongest single-model analytical reasoning                    | Writing could be dense and less reader-friendly                                  |
| Gemini                  | Usable and captured the main financial story                   | Required more debugging, prompt tuning, and token-limit adjustment               |

Overall, I found that the mixed **Claude + GPT-4o** setup produced the best balance. Claude was stronger at deeper business and financial reasoning, while GPT-4o improved the final report’s flow, clarity, and readability.

### 3.4 Track B: Claude-Inspired Workflow Enhancement

For Track B, I implemented a Claude-inspired modular research enhancement. I experimented with three possible research artifacts:

```text
earnings_update.md
thesis_tracker.md
catalyst_calendar.md
```

The final report mainly includes the **Earnings Update** module because it adds the clearest new value without repeating existing sections.

The Earnings Update module was designed to simulate how analysts write post-earnings update notes. After a company reports earnings, analysts usually compare actual results with prior estimates, identify where the company performed above or below expectations, update their assumptions, and explain whether the original investment thesis is still intact.

In my implementation, the module generates:

```text
earnings_update.md
```

This file is then read by the report-generation pipeline and inserted into the final HTML/PDF report as a new **Earnings Update** section.

The Earnings Update module includes:

- Reported results versus internal model estimates
- Year-over-year revenue and margin changes
- Forward estimate table
- LLM-based analyst commentary
- Investment implication discussion

Although I mainly used `earnings_update.md` in the final report, I kept the code for `thesis_tracker.md` and `catalyst_calendar.md` so these two modules can be added back later if needed.

## 7. Summary

In this project, I upgraded FinRobot from both a model perspective and a workflow perspective.

The model experiments showed that each model had different strengths. GPT-4.1 was the most stable baseline and produced complete reports with a consistent structure. GPT-4o improved the readability and polish of the final report. Claude Sonnet 4.6 provided the strongest single-model analytical reasoning, especially in explaining business drivers, valuation, risks, and investment implications. Gemini was usable as a comparison model, but it required more debugging, prompt tuning, and output-token adjustment.

The best overall setup was the mixed Claude + GPT-4o configuration. Claude worked better for deeper financial and business analysis, while GPT-4o made the final report smoother and more reader-friendly. This combination produced a stronger balance between analytical depth, report clarity, and professional presentation than using only one model.

For Track B, the main enhancement was the Claude-inspired Earnings Update module. I also add Catalyst Calendar modeles and thesis Tracker. Earnings Update module added a post-earnings research workflow by comparing reported results with the internal model line, showing year-over-year changes, presenting forward estimates, and explaining the investment implications. I kept the optional code for the Thesis Tracker and Catalyst Calendar modules, the final report mainly used the Earnings Update section because it added the clearest new value.

Overall, this project showed that improving FinRobot requires more than only switching to a stronger model. A good AI equity research system needs a strong base model, careful prompt design, reliable artifact generation, clear engineering structure, and a reproducible workflow. The final improved pipeline produced reports that were more complete, more structured, and closer to a professional equity research process.
